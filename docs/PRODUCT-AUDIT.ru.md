# Продуктовый аудит tile-rs: что довести до финальной версии

Дата: 2026-10-21. База: версия 0.5.0 и ветка `codex/performance-foundation`.
Сравнение проведено с komorebi, GlazeWM, FancyZones (Windows), Hyprland, niri, i3/sway (Linux), AeroSpace (macOS) и PaperWM (GNOME).

## 1. Где tile-rs сейчас

Сильные стороны, которых нет у большинства конкурентов на Windows:
- один `.exe`, установщик и автообновление, работа без прав администратора;
- живой ресайз мышью с перестройкой соседних окон и перетаскивание интервалов между ними; komorebi и GlazeWM здесь управляются в основном с клавиатуры;
- окна сразу открываются в своей плитке, без мерцания;
- графический лаунчер настроек; у komorebi и GlazeWM настройка идёт через JSON или YAML;
- корректная работа с полноэкранными играми и видео.

Позиционирование: **тайлинг для обычного пользователя Windows, а не только для любителей i3**. Каждое решение ниже проверяется вопросом, помогает ли оно человеку без опыта в Linux.

Главные пробелы:
1. Нет быстрого способа временно развернуть одно окно (monocle или fullscreen внутри раскладки). Без этого тайлинг на ноутбуке неудобен.
2. Нет управления главной областью: доля master-окна и число окон в master-колонке.
3. Горячие клавиши редактируются текстом в формате TOML, правила приложений есть только в `config.toml`.
4. Нет первого знакомства: пользователь не знает базовых сочетаний.
5. Нет обзора окон и рабочих столов.
6. Нет внешнего управления (CLI/IPC) для скриптов, AutoHotkey, Stream Deck и панелей.

## 2. Функции: делать / позже / не делать

### P0 — обязательно до «1.0»

| Функция | Источник идеи | Зачем |
|---|---|---|
| **Monocle / развернуть окно** (`toggle_fullscreen`): окно занимает всю рабочую область, остальные остаются на местах | i3, Hyprland `fullscreen 1`, komorebi monocle | Самая частая просьба в тайлинге; нужна на ноутбуках |
| **Доля и количество окон в master** (`master_ratio`, `master_count`, хоткеи `+`/`-`) | dwm, Hyprland master | Сейчас master-stack фиксирован |
| **Переключение на предыдущее окно и рабочий стол** (`focus_last`, `workspace_back_and_forth`) | i3 | Дёшево и очень полезно |
| **Редактор хоткеев в лаунчере**: список действий, запись сочетания нажатием, проверка конфликтов | FancyZones, PowerToys | Текстовый TOML — основной барьер для новичков |
| **Редактор правил приложений**: список запущенных окон → «всегда плавающее / на рабочий стол N / не трогать» | GlazeWM, komorebi (там только конфиг) | Сейчас правила только в TOML; это частая причина «программа ведёт себя странно» |
| **Экран первого запуска**: 3–4 шага с основными сочетаниями и выбором раскладки | PowerToys | Без него пользователь закрывает программу через минуту |
| **Шпаргалка хоткеев** по `Alt+/` или из трея | Hyprland и i3 (сторонние скрипты) | Снимает необходимость помнить сочетания |
| **Восстановление окон при сбое**: при аварийном завершении все скрытые и свёрнутые окна возвращаются | komorebi `restore-windows` | Проверить, что `parked.rs` покрывает и сбой, и закрытие через Диспетчер задач |
| **«О программе» с `AboutSlint`** | лицензия Slint | Юридическое требование |

### P1 — заметно улучшают продукт

| Функция | Источник | Комментарий |
|---|---|---|
| **Scratchpad / special workspace**: окно (терминал, заметки, плеер) выезжает по хоткею и прячется | Hyprland special workspace, i3 scratchpad | Одна из любимых функций у пользователей Hyprland |
| **Своя раскладка для каждого рабочего стола и монитора** | Hyprland workspace rules, GlazeWM | Вертикальному монитору нужны колонки, основному — spiral |
| **Обзор (overview)**: уменьшенные рабочие столы с окнами, клик для перехода, перетаскивание между столами | niri overview, Hyprland hyprexpo | Сильный «вау-эффект»; делать после стабилизации ядра |
| **Группы-вкладки (stack/tabs)**: несколько окон в одной плитке с полоской вкладок | niri tabs, Hyprland groups, komorebi stackbar | Решает проблему «слишком много узких окон» лучше, чем `auto_overflow` |
| **Режимы клавиш (binding modes)**: режим «resize», где стрелки меняют размер без модификатора | i3 modes, Hyprland submaps, GlazeWM | Удобно, но только для опытных: включать опционально |
| **Направление следующего разделения** в spiral (`split_horizontal` / `split_vertical`) | GlazeWM tiling direction, Hyprland `preselect` | Даёт контроль без новых раскладок |
| **CLI и IPC** (`tile-rs msg focus left`, JSON-события через named pipe) | komorebic, hyprctl, niri msg | Нужен для AutoHotkey, Stream Deck и сторонних панелей вроде yasb и Zebar |
| **Затемнение или прозрачность неактивных окон** | Hyprland `dim_inactive`, komorebi | Простая и заметная визуальная подсказка фокуса |
| **Сохранение сессии**: после перезапуска окна возвращаются на свои рабочие столы | — | Через `process` + `class` + `title`; полностью надёжно не будет, об этом нужно предупреждать |
| **Профили мониторов**: при подключении дока включается заданная раскладка | komorebi, Hyprland monitor rules | Ценно для ноутбуков |

### P2 — позже, если останутся силы

- **Scrolling-раскладка, как в niri и PaperWM.** Окна стоят в ленте колонок, новое окно не сжимает остальные, лента прокручивается. Идея сильная и подходит для широких мониторов, но для Windows это крупная работа: окна за пределами экрана нужно прятать, переход между ними анимировать. Делать отдельной раскладкой после стабилизации. Если будете продавать Full-версию, это хороший кандидат для неё.
- Наборы ширины колонок по циклу (`preset_column_widths` из niri: 1/3, 1/2, 2/3).
- Градиентная или анимированная рамка фокуса (niri, Hyprland).
- Жесты тачпада для переключения рабочих столов: в Windows их перехватывает система, сделать надёжно сложно.
- Именованные рабочие столы и иконки приложений в индикаторе.

### Pro — отложено на платную версию

- **Ресайз через живые миниатюры DWM («snapshot resize»).** Во время перетаскивания разделителя
  настоящие окна не меняют размер: поверх монитора показывается окно-хост, в котором через
  `DwmRegisterThumbnail` / `DwmUpdateThumbnailProperties` живые миниатюры окон масштабируются в
  будущие тайлы (с сохранением пропорций, обрезкой от левого верхнего угла и `rcSource` по
  видимой рамке, без невидимых границ). Настоящий ресайз происходит один раз при отпускании.
  Включать как `live_resize = "snapshot"` только в сборке с cargo-фичей `pro`; в бесплатной сборке
  значение отклоняется с понятной ошибкой. Для перетаскивания края окна режим неприменим (окно
  тянет сама Windows), там остаются контуры. Риски: фон в промежутках между тайлами, захваченная
  мышью ручка разделителя должна оставаться над хостом, поведение на окнах с аппаратным
  ускорением и защищённым содержимым (видео с DRM) нужно проверить вручную.

### Не делать

| Идея | Почему |
|---|---|
| Собственная статус-панель (аналог waybar или komorebi-bar) | Большая работа и постоянная поддержка; лучше отдавать события через IPC для yasb и Zebar |
| Размытие (blur) и скругления окон | В Windows 11 их даёт DWM, своя реализация ломается на чужих окнах |
| Плагины и скриптовый язык | Для небольшого проекта это огромная поверхность для багов; CLI/IPC закрывает 90% потребностей |
| Шейдеры анимаций | Эффектно, но пользы мало, а нагрузка на поддержку большая |
| Встроенный лаунчер приложений и скриншотер (как в niri) | Это задачи PowerToys Run, Flow Launcher и Snipping Tool |
| Динамическое число рабочих столов (как в niri) | Ломает привычные `Alt+1..9` и индикатор; текущие 9 рабочих столов проще |
| Ещё больше раскладок ради количества | Четырёх достаточно, полезнее настраиваемость существующих |

## 3. Опыт взаимодействия (UX)

1. **Предсказуемость.** Если окно не тайлится, пользователь должен понять почему. Добавить пункт в трее «Почему это окно не в раскладке?»: он показывает сработавшее правило (плавающее, полноэкранное, исключено системой) и даёт кнопку «Всегда тайлить».
2. **Безопасная пауза.** Иконка в трее меняет вид на паузе. Пауза по хоткею показывает короткое уведомление.
3. **Отмена.** Хоткей «вернуть раскладку» после случайного перетаскивания. Escape уже работает для интервалов, его нужно распространить на остальные действия мышью.
4. **Подсказки при наведении** на настройки лаунчера: что изменится, с маленькой анимацией.
5. **Ошибки конфигурации.** При ошибке в `config.toml` показывать уведомление со строкой и текстом ошибки и продолжать работу на последней рабочей конфигурации.
6. **Один язык интерфейса.** Сейчас лаунчер на русском, а README, трей и окно обновлений частично на английском. Нужен выбор языка (RU/EN) и единый словарь строк.
7. **Применение без «Сохранить»** для безопасных параметров: интервалы, цвета, анимации меняются сразу (как в PowerToys), кнопка «Отменить изменения» остаётся.
8. **Статус в лаунчере**: «tile-rs запущен» сейчас статичен. Показывать реальное состояние (работает / на паузе / не запущен) и кнопку управления.

## 4. Лаунчер: красивее и понятнее

Текущая структура (`ui/launcher.slint`): левая навигация, карточки настроек, тёмная тема, мятный акцент. Основа хорошая. Что изменить:

**Структура разделов.** Сейчас разделы повторяют поля конфига. Нужно группировать по задачам пользователя:
- **Главная**: статус, текущая раскладка с превью, 3 самых нужных переключателя, подсказки сочетаний;
- **Раскладка**: выбор и превью, интервалы, master, минимальные размеры;
- **Внешний вид**: рамка, индикатор, анимации с живым предпросмотром;
- **Клавиши**: редактор с поиском и записью сочетаний;
- **Приложения**: правила и список запущенных окон;
- **Мониторы**: схема мониторов, своя раскладка для каждого;
- **Система**: автозапуск, обновления, диагностика, «О программе».

**Визуальная часть.**
- Цвета вынести в токены `AppTheme`; сейчас в `launcher.slint` много зашитых значений (`#edf2f4`, `#829099` и др.).
- Поддержать светлую тему и системный выбор темы Windows.
- Окно с Mica-фоном Windows 11, если Slint позволит; иначе аккуратный плоский фон.
- Типографическая шкала из 4–5 размеров вместо 9–23 px вразнобой; минимальный текст — 11 px (сейчас есть подписи 9–10 px, они плохо читаются).
- Иконки в навигации (Segoe Fluent Icons есть в Windows 11; для Windows 10 — запасной SVG-набор).
- Превью раскладки с реальным числом окон пользователя и реальными интервалами, а не только схемой.
- Адаптивная вёрстка: одна колонка карточек на узких экранах (сейчас минимум 1000 × 640).

**Понятность.**
- У каждой настройки подпись в одну строку на понятном языке, техническое имя ключа — мелко или в подсказке.
- Признак несохранённых изменений и кнопка «Сбросить к умолчаниям» в каждом разделе.
- Проверка чисел рядом с полем, а не при сохранении.

## 5. Надёжность перед финальной версией

- Сквозной тест обновления между двумя версиями (уже указан в `LAUNCHER-AUDIT.ru.md`).
- Подпись кода: SignPath Foundation (бесплатно для open source) или Microsoft Store.
- Тесты на сложных окнах: UWP, Electron (Discord, VS Code), окна с правами администратора (их нельзя двигать из процесса без прав), DPI 100/150/200% на разных мониторах, отключение и подключение монитора, сон и пробуждение.
- Лог диагностики с кнопкой «Собрать отчёт» в лаунчере: версия, конфиг, список окон без заголовков — для issue на GitHub.

## 6. Порядок работы

1. **0.6 — основа:** monocle, master ratio/count, focus last, восстановление окон при сбое, «О программе», единый язык, уведомление об ошибке конфига.
2. **0.7 — лаунчер:** новая структура разделов, токены темы, редактор хоткеев, редактор правил, первый запуск, шпаргалка.
3. **0.8 — сила:** scratchpad, раскладка для каждого рабочего стола и монитора, направление разделения, CLI/IPC, затемнение неактивных окон.
4. **0.9 — эффект:** overview, группы-вкладки, профили мониторов, сохранение сессии.
5. **1.0:** подпись кода, сквозные тесты, документация, Store.
6. **После 1.0:** scrolling-раскладка в стиле niri.
