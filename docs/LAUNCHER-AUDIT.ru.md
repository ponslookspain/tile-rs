# Аудит лаунчера tile-rs

## Реализация

Лаунчер написан на Slint и запускается отдельным процессом (`--launcher-ui`). Это правильное разделение: UI и сетевые запросы не блокируют Win32-цикл менеджера окон. Настройки сохраняются атомарно; менеджер получает команду перечитать конфигурацию. Эти механизмы сохранены.

## Найдено и исправлено

| Проблема | Изменение |
| --- | --- |
| В двух местах была зашита версия 0.4.0 | Версия берётся из Cargo.toml |
| У четырёх раскладок был один символ | Отдельные геометрические схемы и анимированный предпросмотр выбранной раскладки |
| Мелкий текст, слабая иерархия и одинаковые состояния | Единые цвета, более крупные подписи, карточки, мятный акцент, состояния hover/press/focus |
| Самодельные кнопки работали только мышью | Tab, Enter, Space и accessibility-метки основных элементов |
| Фиксированные высоты могли скрывать настройки | Прокрутка содержимого при сохранении видимости навигации и кнопки сохранения |
| Поля Slint растягивались за пределы колонки | Явные ограничения ширины числовых полей и высоты выпадающих списков |
| Проверка обновлений показывала только ссылку | Полный экран проверки, версии, описания релиза, загрузки, ошибок и установки |
| Пользователь не узнавал о релизе | Фоновая проверка через 15 секунд после запуска и затем каждые 6 часов, уведомление в трее |

Анимации переключателей, цветов и схем раскладки отключаются вместе с настройкой анимаций. Предпросмотр схематический: он показывает структуру раскладки, а не реальные окна или точный масштаб интервалов.

## Обновления

Путь пользователя: уведомление Windows → страница «Обновления» → Check update → «Установить обновление» → загрузка и SHA-256 → установщик → перезапуск. Нажатие уведомления открывает страницу и в уже запущенном экземпляре лаунчера. Установка выполняется только по нажатию кнопки.

Источник — последний стабильный GitHub Release. Workflow запускается при push тега `v*`, сверяет версию с Cargo.toml и публикует установщик с `.sha256`. Push обычного коммита не создаёт обновление. Процедура описана в [RELEASING.md](RELEASING.md).

Сеть работает в отдельных потоках. Проверяются версия, ожидаемые имена и адреса файлов, размер загрузки и контрольная сумма. До успешного скачивания, проверки и готовности вспомогательного процесса менеджер продолжает работать. Сохраняются конфигурация и фактическая настройка автозапуска.

## Ограничения и следующие шаги

- Старые версии без этого механизма нужно один раз обновить вручную. Добавить функцию в уже установленный бинарный файл через GitHub невозможно.
- Портативная копия обновляется установщиком в ту же папку и становится зарегистрированной установкой. Для полностью портативного обновления нужен отдельный сценарий замены из ZIP.
- Контрольная сумма защищает от повреждения загрузки; доверие издателю зависит от GitHub и настроенной подписи Windows. Workflow уже поддерживает секреты для подписи.
- Минимальное окно — 1000 × 640 логических пикселей. Для ещё более узких экранов потребуется переход двухколоночных карточек в одну колонку.
- Следующие полезные улучшения: признак несохранённых изменений, проверка чисел рядом с полем и редактирование горячих клавиш без TOML.
- Перед распространением необходим сквозной тест двух разных версий на Windows: установка → обнаружение следующего Release → обновление → перезапуск, включая отмену установщика и папку с ограниченными правами. В этой сессии реальная установка релиза не выполнялась.

## Проверка

Сборка и проверки Rust дополняются визуальным просмотром нативного окна с отдельной конфигурацией внутри `target/ui-preview`. Настройки рабочего экземпляра не сохранялись через тестовое окно. Сетевой запрос в тестовой среде вернул ошибку соединения; проверено корректное отображение ошибки и повторной проверки. Unit-тесты обновления не используют сеть и не запускают установщик.
